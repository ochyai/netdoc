# netdoc

この Mac で変更できる原因を直し、変化を測る。ルーターや上流回線など手の届かない問題は、
疑いの根拠と次に絞る方法を示す。既存の CLI を使い、診断スクリプトをその場で作り直さない。

## 実行

`command -v netdoc` と `netdoc --help` で導入済みの実体と対応オプションを確認する。
CLI が見つからなければ、このスキルと同じリポジトリの `netdoc` を使う。
配置・各コマンドの詳細は [README](../../README.md) を読む。本体と `lib/` を一緒に扱う。

| 依頼 | 入口 |
|---|---|
| 原因を知りたい・変更したくない | `netdoc --plan`。速度測定不要の疎通調査なら `--check` |
| 全体が遅いので直したい | `netdoc --fix`。根拠と依頼範囲に合う候補を実行 |
| 無人で修復したい | `netdoc --auto`。権限不足・対象外は結果として残す |
| LLM だけ繋がらない | `netdoc --llm`。生成初動の測定を依頼されたときは `--stream` |
| 変更を戻したい | `netdoc --restore` または `netdoc --restore ID` |

会議中など、回線への負荷を避ける条件があれば `--check` や `--where` から始める。
`--plan` も速度測定で回線に負荷をかけるため、設定変更がないことと通信への影響がないことを区別する。

診断だけの依頼から設定変更へ拡張しない。修復まで依頼されている場合、既に許可された操作に
再確認を挟まない。CLI が処置の選択を求めたら、観測結果と依頼された範囲に照らして選ぶ。
`--auto` でスキップされた操作を無条件に対話版へ切り替えて実行しない。

速度測定は回線を使う。前後比較では同じ接続と測定条件を保ち、測定中の別ダウンロード等が
あれば結果に付記する。失敗、タイムアウト、欠測を 0 Mbps や正常と読み替えない。

## 結果の読み方

- Wi-Fi の PHY リンク速度をインターネット実効速度と比較しない。信号が良好でも、
  同一チャネルの混雑や AP の処理待ちは除外できない。
- ゲートウェイと複数の外部宛先を比較する。外部だけで ICMP 欠落が繰り返されれば上流は候補だが、
  応答制限や ICMP の優先度もあり、実際の HTTPS 応答や有線・別回線の結果と合わせる。
- 負荷前と負荷中の応答時間を見る。転送速度が出ていても、通信中の遅延増大で Web 等が遅くなり得る。
  1接続のダウンロードと複数接続による測定は条件が違うため、単純に同じ値を期待しない。
- アプリの帯域占有は `nettop` の区間差分で見る。初回の累計値を現在の通信量として扱わない。
  この Mac の通信量が少なくても、他端末やルーターの混雑までは除外できない。
- Tailscale は JSON の exit node 状態と実際の経路を確認する。インストール済み・起動中という理由で止めない。
- DNS の回答差だけで書き換え、未知の証明書発行者だけで TLS 傍受を断定しない。
  単発の ping 欠落や失敗した MTU 探索を根拠に MTU・IPv6 を変更しない。

## 修復の扱い

CLI の記録・復元機構を使い、1つの処置ごとに結果を評価する。変更前の設定を保存できない場合は、
復元可能な設定変更として扱わない。キャッシュ消去など元の内容を復元できない操作も区別する。
HTTP が1回返っただけで「速度が直った」としない。DNS 変更は名前解決と疎通の改善を確認できなければ
CLI が復元する。復元の失敗があれば、その状態と保存した記録を明示する。
`--restore` の対象は保存した DNS 設定である。同じ証拠のまま修復を反復しない。

`--fix` / `--auto` は実行した処置の後に DNS・疎通の改善を確認すると、速度と負荷時遅延も自動で再測定する。
表示される前後の値と性能の結果を使い、成功した測定を理由なく `--speed` で繰り返さない。
修復なし・効果未確認なら追加の負荷測定は行われない。会議中の `--check` にも追加しない。
DNS・疎通の回復と、回線全体に残る遅さや性能の欠測を分けて報告する。
時間帯や測定先の変動があるため、前後の差だけで修復が速度変化を引き起こしたと断定しない。

帯域を使うアプリを見つけても自動終了・一括停止しない。ユーザーが指定したプロセスを一時停止する場合は、
現在の PID と対象を確認して `netdoc --pause PID 秒` を使う。既定60秒・最大300秒で再開し、`kill` で終了させない。
PID の列挙だけを停止の許可とは扱わない。

最終報告には、詰まりの候補と確度、実行した処置、比較できた前後の数値、残った問題を短く示す。
ルーターや ISP の設定を操作できない場合は、修復完了を装わず、有線・別回線との比較など次の切り分けを示す。
IP、SSID、端末名、診断ログを公開リポジトリや外部の相手へ勝手に送らない。
