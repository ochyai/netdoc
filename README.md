# netdoc 🩺

**Web・動画・ダウンロードが遅い原因を調べ、直せる箇所を修復して測り直す** macOS 用ネットワークドクター。

Wi-Fi、ルーターまでの通信、外部回線、DNS、VPN、通信中のアプリを切り分けます。
LLM API や手元・tailnet 上の ollama / LM Studio / llama.cpp の疎通診断も使えます。

```bash
netdoc --fix       # 速度込みで診断 → 根拠のある修復 → 手で試す修復メニュー(10項目) → 再測定
netdoc             # 同上を速度測定なしで（会議中はこちら）
netdoc --plan      # 診断と修復案だけ。設定を変更しない
netdoc --auto      # 根拠のある軽い修復だけを無人で実行
netdoc --restore   # 記録した DNS 設定変更を戻す
```

「HTTP が返った」だけでは速度が改善したとは判定しません。DNS 設定を変更した場合は、
名前解決と疎通の改善を再検証し、確認できなければ設定を戻します。
`--fix` / `--auto` は実行した修復の効果を確認後、速度と負荷時の応答も自動で測り直します。
ルーターの混雑やプロバイダー側など、この Mac から修復できない問題は未解決として残します。

## インストール・更新

```bash
git clone https://github.com/ochyai/netdoc.git ~/netdoc
mkdir -p ~/bin
ln -sf ~/netdoc/netdoc ~/bin/netdoc
```

`~/bin` が PATH に入っていなければ、`~/.zshrc` に `export PATH="$HOME/bin:$PATH"` を追加して
ターミナルを開き直してください。既存の clone は `git -C ~/netdoc pull --ff-only` で更新できます。

**本体と `lib/` を一緒に置いてください。** 以前の1ファイルだけをダウンロードする方法には対応しません。
macOS 標準の bash 3.2 とシステムコマンドを使います。`jq` があれば JSON 出力を整形できます。

## コマンド

| コマンド | 用途 |
|---|---|
| `netdoc` | 対話形式の診断と修復 |
| `netdoc --fix` | 速度込みの診断、根拠のある修復、手で試す修復メニュー、変更前の記録、修復後の比較 |
| `netdoc --plan` | 速度込みの診断と修復案。設定変更なし |
| `netdoc --auto` | 無人実行できる根拠のある軽い修復。sudo 認証が必要なら待たずにスキップ |
| `netdoc --check` | 基本診断のみ。設定変更なし |
| `netdoc --speed` | 回線速度と遅延を詳しく測定 |
| `netdoc --full` | 速度測定まで含めた全体診断。設定変更なし |
| `netdoc --where` | IP、ISP、Wi-Fi、経路など接続状態 |
| `netdoc --llm` | LLM の DNS → TCP → TLS → HTTP 疎通 |
| `netdoc --stream` | 実際にモデルを動かし、最初のトークンまでの時間を測定 |
| `netdoc --history` | このネットワークでの過去の記録 |
| `netdoc --json` | 診断結果を JSON で出力 |
| `netdoc --report [PATH]` | 診断結果を Markdown に保存 |
| `netdoc --watch [SEC]` | 定期診断。状態の変化時に表示 |
| `netdoc --targets` | LLM の診断先一覧 |
| `netdoc --discover` | 手元と tailnet の LLM サーバを探して登録 |
| `netdoc --restore [ID]` | 記録した DNS 設定変更を復元。ID 省略時は最新 |
| `netdoc --restore-dns` | DNS の復元用互換コマンド |
| `netdoc --pause PID [秒]` | 指定したユーザープロセスを一時停止し、自動再開。既定60秒、最大300秒 |

速度測定は外部へデータを送受信します。測定中は回線に負荷がかかり、
所要時間は回線状態とタイムアウトによって変わります。

## 遅さの切り分け

| 観測 | 分かることと限界 |
|---|---|
| Wi-Fi の信号、チャネル、リンク速度 | 電波と接続状態。リンク速度は実効速度ではなく、電波が良好でも AP の混雑は残る |
| ゲートウェイと複数の外部宛先への応答 | 手元からルーターまでと、その先を比較。ICMP の欠落だけでは実際のパケット損失と断定しない |
| 負荷前と通信中の応答時間 | ダウンロードやアップロード中に待ち時間が増えるか |
| 実際の送受信速度 | 宛先・接続方式による差。1回の測定値だけで回線契約の上限とは判断しない |
| DNS と HTTPS の応答 | 名前解決の遅さか、接続後も遅いか |
| アプリごとの現在の通信量 | この Mac 内で帯域を使っている候補。累計値と測定区間の通信量を区別する |
| Tailscale、exit node、経路、プロキシ | 実際にその経路を通っているか。VPN が起動しているだけでは原因としない |

例えば、ルーターへの応答が安定し、複数の外部宛先で欠落や遅延が繰り返されるなら、
上流回線は候補になります。ただし相手側の ICMP 応答制限もあり、有線や別回線との比較で絞ります。
この Mac の通信量が少なくても、同じネットワークの別端末が帯域を使っている可能性は残ります。

## 修復と復元

修復は2段構えです。まず診断の根拠に合う処置（DNSキャッシュ・DNS固定・DHCP再取得）を提案し、
その後 **手で試す修復メニュー** を上から順に聞きます。根拠が揃わなくても、経験上よく効く順です。

| # | 処置 | 既定 | 戻し方 |
|---|---|---|---|
| 0 | captive portal をブラウザで開く（検出時のみ） | Y | — |
| 1 | DNSキャッシュを消す | Y | 不要 |
| 2 | DHCPリースを取り直す | Y | 自動 |
| 3 | DNSを 1.1.1.1 / 8.8.8.8 に固定 | N | `netdoc --restore`（再テストで名前解決が通らなければ自動で戻す） |
| 4 | Tailscale の exit node を外す（使用時のみ） | Y | `tailscale set --exit-node=...` |
| 5 | Tailscale を切る／繋ぐ | N | `tailscale up` / `down` |
| 6 | プロキシ環境変数を外して疎通だけ試す（設定時のみ） | Y | 設定は変えない |
| 7 | 経路MTUを実測し、低ければ合わせる | N | 表示される `ifconfig ... mtu` |
| 8 | 時計を合わせる（2分以上ずれた時のみ） | Y | — |
| 9 | IPv6 を切る | N | 表示される `networksetup -setv6automatic` |
| 10 | Wi-Fi を切って入れ直す | N | — |

各項目は y/n で選び、Enter だけなら既定、Ctrl-D や入力の終端は「いいえ」です。
sudo が要る項目は選んだ後に認証を求めます。`--auto` ではこのメニューは出ません。
実行後に名前解決・HTTPS・api.anthropic.com を再テストし、「通っている／まだ繋がらない」を出します。
通っていても体感が変わらなければ、残りの候補は AP・ルーター・ISP 側です。


`--fix` は診断で根拠が得られた候補を表示し、選択された処置を実行します。
DNS 変更前の設定を `~/.netdoc/repairs/ID` に保存し、同じ宛先で修復前後の症状を比較します。
権限が必要な処置では `sudo` を使います。`--auto` は非対話で可能な軽い修復に絞り、パスワード入力を待ちません。

現在の修復対象は、システムの DNS キャッシュ、失敗が確認された DNS 設定、
DHCP 設定なのに IPv4 を取得できていない状態です。`--auto` が実行するのは DNS キャッシュ消去のみです。

`--fix` / `--auto` は DNS と複数宛先への疎通の改善を確認すると、回線性能を再測定し、
下り・上り・単一接続の速度、平常時・負荷時の応答時間を変更前の値と並べて表示します。
修復を実行していない場合や効果を確認できなかった場合は、追加の負荷測定を行いません。
名前解決が直っても、回線の遅さが残る場合や性能測定が成立しない場合は、その結果を分けて表示します。
数値には時間帯や測定先の変動も含まれるため、前後の差だけで修復との因果関係は確定しません。

DNS キャッシュの消去は、名前解決に問題がある場合の候補です。公開 DNS への変更などの設定操作は、
診断の裏付けと復元手段を持たせます。DNS の回答が違うだけで書き換えと決めつけたり、
単発の ping の欠落から MTU や IPv6 を変更したりはしません。

帯域を使っているアプリを見つけても、自動では終了・停止しません。
対象を選んで一時停止する場合は、表示された PID を指定します。

```bash
netdoc --pause 12345 60
```

プロセスを終了させず、`STOP` / `CONT` で一時停止と再開を行います。
一時停止中はそのアプリの処理も止まるため、保存・同期・会議など実行中の作業を見て対象を選んでください。

変更を後から戻すには次を実行します。個別の記録に戻す場合は、表示された ID を指定します。

```bash
netdoc --restore
```

キャッシュ消去や DHCP 再取得は、以前のキャッシュ内容・リースへの復元には対応しません。
DNS の復元は保存時と同じネットワークで行い、途中で別の値に変更された設定は上書きしません。
回線側が原因で解消できなければ、有線接続での比較、他端末の通信量確認、ルーターや ISP の調査など、
測定結果から必要な次の手順を示します。管理権限や比較できる別経路がなければ、ルーター・上流回線自体は修復できません。

## Codex / Claude Code スキル

スキルの正本は [`skills/netdoc/SKILL.md`](skills/netdoc/SKILL.md) です。
CLI のインストール後、使うアシスタントのスキルディレクトリにリンクします。

```bash
mkdir -p ~/.codex/skills
ln -s ~/netdoc/skills/netdoc ~/.codex/skills/netdoc

# Claude Codeにも同じ正本を登録
mkdir -p ~/.claude/skills
ln -s ../../netdoc/skills/netdoc ~/.claude/skills/netdoc
```

Codex で `$netdoc 回線全体が遅いので、原因を調べて直せるところまで直して` と依頼できます。
Claude Codeでも同じ `netdoc` スキルを使います。別のMacでスキルのリンクを同期する場合も、先に `~/netdoc` をclone・更新してください。両方が同じファイルを参照するため、手順の更新は共通です。
診断だけの依頼では設定を変えず、修復まで依頼された場合は許可された範囲で進めます。

## LLM の接続診断

```bash
netdoc --llm
```

登録した宛先ごとに DNS、TCP、TLS、HTTP を分けて調べます。
公開 DNS との回答の差、証明書の発行者、プロキシ認証や captive portal も確認します。
CDN や社内 DNS による回答の差、独自 CA などの事情があるため、差や発行者名だけで傍受を断定しません。

`ollama` では `/api/tags` のモデル一覧や `/api/ps` のロード状態を確認します。
HTTP 応答時間は最初のバイトまでの時間（TTFB）です。
モデルの読み込みや生成の初動は、明示的な `netdoc --stream` で測定します。
このコマンドは実際に生成を要求するため、通常の疎通診断とは分けています。

診断先は `~/.netdoc/targets.conf` に保存されます。手で編集するか、
`netdoc --discover` で手元と tailnet の応答するサーバを登録できます。

```text
# 名前 | URL | 種別(http|ollama|openai)
Anthropic API     | https://api.anthropic.com/ | http
ollama (ローカル)  | http://127.0.0.1:11434     | ollama
社内API           | https://llm.example.com    | openai
```

## 記録

設定、診断履歴、修復記録は `~/.netdoc/` に置きます。ネットワークごとの履歴は
`~/.netdoc/history.tsv` に保存し、前回の測定との違いを表示します。
記録やレポートには IP、SSID、宛先、アプリ名などの接続情報が含まれることがあります。
共有する際は内容を確認してください。個人の実測ログはリポジトリへ追加しません。
